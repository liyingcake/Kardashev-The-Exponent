## 决策记录

### D-19 ｜ 2026-08-13 ｜ v6 立项：表现层从"抽象表单"转向"可视化节点编辑器"
- **触发**：用户反馈 v5"太抽象了，需要更符合人类审美的、习惯的，可视化节点内置窗口，中间是演示图，下面是节点操作窗口"。
- **诊断**：v5 的机制（通配符/权重/逆熵）是对的，但暴露方式是**裸标签 + 下拉表单**（`matter:raw`、`energy:useful`、select 框），工程师化、反直觉。用户要的是**节点编辑器范式**（Upload Labs / 蓝图 / 流程图那种大众熟悉的视觉）。
- **决策**：
  1. **引擎 100% 保留**（通配符匹配、逆熵结算、权重、EROI）——data.js 直接复用。
  2. **节点可视化**：节点画成"带窗口样式的圆角矩形"，内置标题栏（图标+人类可读名）+ 数据区 + 输入/输出端口。
  3. **布局重构**：中间 = 演示图（Canvas 节点画布），下面 = 节点操作窗口（选中节点时出现）。
  4. **人类可读命名**：所有裸标签（`matter:raw` 等）在 UI 层翻译成"⛏️ 原料·物质"这类中文+图标；通配符翻译成"任意原料""可用能量"等。
- **性质**：表现层转向，不推翻机制。重点是把"抽象"翻译成"人类审美的可视化"。

### D-20 ｜ 2026-08-13 ｜ 连线可视化 = 按逆熵链顺序推断
- **决策**：v5 是"全局流池 + 通配符"，无显式连线。v6 为可视化，按逆熵链顺序**推断连线**：source→process→settle→collect，连线颜色按流域（物质=绿/能量=黄/信息=蓝）。
- **依据**：用户要"演示图"，需要看得见节点之间的流；推断连线是对"全局池"的可视化降维。

### D-21 ｜ 2026-08-13 ｜ MVP 裁切
- **保留**：可视化节点图 + 底部操作窗口 + 通配符(人类可读) + 权重滑块 + 流库存(人类可读)。
- **延后**：节点拖拽、自由连线、路由窗口接线、危机裁决。
