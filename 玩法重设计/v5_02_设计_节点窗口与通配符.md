# v5 设计 —— 节点窗口 × 通配符 × 策略权重

> 日期：2026-08-13 ｜ 定位：v5 主设计。**节点 = 窗口，资源 = 带标签的抽象流，规则 = 通配符，参数 = 策略权重。**
> 依据：`v5_01_反思` + Upload Labs 已核实机制（Steam 3606890）。

---

## 0. 主题：文明 = 逆熵体（对抗热寂）

Upload Labs 的主题是"**save the universe from the inevitable heat death**"（拯救宇宙免于热寂）。这恰好就是卡尔达肖夫指数的物理本质：

> **文明 = 局部的低熵体。K 指数 = 文明把无序能量转化为有序结构（逆熵）的速率与规模。**

- 能量被"利用" = 能量**逆熵**（从无序到有序），而非被"烧掉"（熵增）。
- **EROI = 逆熵效率**：每投入一份能量，能造出多少份有序结构。
- 每一次转化**必然产生废热**（热力学第二定律，呼应 Upload Labs 的 heat 公式）——所以 EROI 有天花板，永远 < ∞。

一句话：**玩家不是在"经营农场"，而是在"设计一个对抗熵增的系统"。**

---

## 1. 抽象资源：带标签的流（Stream）

不再有 `wood / food / cooked_food` 这种写死的实体。资源是一个**抽象流**，携带属性标签，节点用**通配符**匹配它。

### 1.1 两个标签维度

| 维度 | 取值 | 含义 |
|---|---|---|
| **域 domain** | `matter` 物质 / `energy` 能量 / `info` 信息 | 流的本质 |
| **阶段 stage** | `raw` 原料 / `refined` 精炼 / `useful` 有用 / `waste` 废热 | 流在逆熵链上的位置 |

> 一个流 = `domain:stage`，如 `matter:raw`（物质·原料）、`energy:useful`（能量·有用）、`info:useful`（信息·有用）。
> 未来可加第三个标签 `quality`（品质），MVP 先二维。

### 1.2 为什么是"标签"而不是"实体"

- 加一种资源 = 加一个标签组合，**零硬编码**（Upload Labs 的 modifier 思维）。
- 节点按"标签模式"匹配流，而不是按"名字"找具体物品——这就是**通配符**的来源。

---

## 2. 通配符（Wildcard）：节点的规则语言

### 2.1 语法

| 通配符 | 匹配 |
|---|---|
| `*` | 任意（任意域、任意阶段） |
| `matter:*` | 任意阶段、但域=物质 |
| `*:raw` | 任意域、但阶段=原料 |
| `matter:raw` | 精确匹配 |

### 2.2 节点用通配符声明"吃什么 / 产什么"

每个节点窗口有：
- **输入端口**：一个通配符（如 `*:raw`）——它接受所有"原料阶段"的流，无论来自森林还是农田。
- **输出端口**：一个通配符（如 `energy:useful`）——它产出"能量·有用"。

**关键**：同一个"加工"窗口，玩家改通配符，就从"灶火"变成"水力"变成"太阳能"——节点的**行为是配置出来的，不是写死的**。

## 3. 节点窗口（Node Window）

### 3.1 窗口结构（Upload Labs 的 window-like interface）

```
┌────────────────────────────────────┐
│ ◉ 加工窗口 · Process          [×]  │ ← 标题栏（类型 + 可命名）
│ ────────────────────────────────── │
│ 输入  [*:raw        ▼]            │ ← 通配符选择器（吃什么）
│ 输出  [energy:useful ▼]            │ ← 通配符选择器（产什么）
│ ────────────────────────────────── │
│ 策略权重                            │
│   逆熵效率  [=====-----] 50%        │ ← 权重滑块①
│   吞吐规模  [-------==] 30%        │ ← 权重滑块②
│   稳定性    [====------] 20%        │ ← 权重滑块③
│ ────────────────────────────────── │
│ EROI ≈ 6.2 ｜ 熵增(废热) 34%      │ ← 实时效率
└────────────────────────────────────┘
```

### 3.2 五类窗口（按"逆熵链上的位置"分类，非具象名）

| 窗口类型 | 职责 | 默认输入 | 默认输出 |
|---|---|---|---|
| **采集 Source** | 从环境获取原料 | `∅`（环境） | `matter:raw` / `energy:raw` |
| **加工 Process** | 逆熵转化（能量在此被利用） | `*:raw` | `*:useful` / `*:refined` |
| **路由 Route** | 分配/运输，带吞吐 | `*:*` | `*:*`（转发） |
| **消费 Settle** | 定居点消费，产出劳动力+科技 | `*:useful` | `info:useful` + 人口 |
| **收集 Collect** | 汇总窗口，承载乘数 | `*:*` | `∅`（K 指数） |

> 观察：**这五类就是 v4 的"采集/加工/定居/收集"的抽象化**——不是推翻，是把"森林/灶火/农田"这些具象名替换成"可配置的窗口"。

### 3.3 窗口内可调（高度可调的策略权重）

每个窗口有**一组权重滑块**（0–100%），决定该窗口的行为倾向：

| 权重 | 作用 | 举例 |
|---|---|---|
| **逆熵效率** | EROI 高、废热少，但慢 | 拉高 → 加工干净但吞吐低 |
| **吞吐规模** | 产出量大，但废热多、EROI 低 | 拉高 → 堆产量、耗燃料 |
| **稳定性** | 抗危机、波动小 | 拉高 → 不易崩，但牺牲效率 |

**这就是用户要的"窗口化的节点可以高度可调策略权重方式"**——每个节点都是一个可调的小策略面板。

## 4. 统一乘数：从"写死公式"到"窗口权重之和"

v4 的乘数是写死的 `integrationMult() × scaleMult()`。v5 改为：

```
文明总乘数 = 基序 × Π(每个窗口的权重贡献) × 国策 × 技术
```

- **基序** = 逆熵链完整度（采集→加工→消费闭合环数量）——统合奖励保留。
- **窗口权重贡献** = 每个窗口自己的权重滑块，直接乘进去（玩家调窗口 → 乘数变）。
- **国策/技术** = 全局倾向，映射为对某类窗口的加成。

> 一个窗口、一个小乘数：**窗口是乘数的"旋钮"，玩家拧旋钮 = 调乘数**。

## 5. 能量利用 = 逆熵（EROI 语义）

### 5.1 旧语义（v4，半对）

```
燃料(木柴) + 原料(生食) →[加工]→ 加工品(熟食) →[消费]→ 劳动力+科技
```

### 5.2 新语义（v5，抽象）

```
matter:raw ──┐
energy:raw ──┼→[加工窗口, 通配符:*:raw→*:useful]→ energy:useful ─→[消费窗口]→ info:useful + 人口
             └──(必产废热 energy:waste，热力学约束)──┘
```

- **能量是被"利用"来做逆熵的中介**：把低阶流（raw）提升到高阶流（useful）。
- **EROI = 逆熵效率**：`energy:useful 产出 / (energy:raw 投入 + matter:raw 投入)`。废热越多，EROI 越低。
- **K 指数 P = 有用能量流的消费速率**——文明强不强，看它把能量逆熵到了多少件有意义的事。

## 6. MVP 落地（demo-v5）

### 6.1 最小闭环

```
[采集窗口] → matter:raw, energy:raw
      ↓
[加工窗口]（通配符 *:raw → energy:useful）→ energy:useful（+ energy:waste 废热）
      ↓
[消费窗口]（通配符 energy:useful → info:useful）→ info:useful + 人口 + 科技
      ↓
[收集窗口] → K 指数 + 统一乘数
```

### 6.2 玩家在 v5 里做什么

1. **点开任意窗口** → 看到通配符选择器 + 策略权重滑块。
2. **改通配符** → 让加工窗口从"吃 `matter:raw`"变成"吃 `*:raw`"（能吃能量原料了）。
3. **拖权重** → 逆熵效率↑（EROI 高但慢）vs 吞吐规模↑（堆量但废热多）。
4. **看废热** → 每个窗口实时显示 EROI 与废热占比，玩家理解"逆熵有代价"。

### 6.3 验证目标（MVP）

1. 玩家 5 分钟内理解"节点是窗口、流是标签、规则是通配符、参数是权重"。
2. 改通配符/拖权重 → 30 秒内看到流与 EROI 变化。
3. 无死锁：默认窗口配置即可跑通闭环。

## 7. 与 v4 / 既有锚点的关系

| 锚点 | 处置 |
|---|---|
| K 指数 = (log₁₀P−6)/10 | **保留**，P 重新定义为"有用能量流的逆熵速率" |
| EROI 硬约束 | **保留**，升维为"逆熵效率"，废热显式化 |
| 上帝视角 | **保留**，玩家仍是引导者，操作单位=窗口 |
| 节点载体 | **保留**，从"具象物体"改为"可配置窗口" |
| 资源 | **重构**，从"硬编码实体"改为"带标签抽象流 + 通配符" |
| 乘数 | **重构**，从"写死公式"改为"窗口权重之和" |

## 8. 一句话裁决

> **把《文明指数》重铸为一个"逆熵系统设计器"：节点是窗口，资源是带标签的抽象流，规则是通配符，参数是策略权重——玩家拧每一个窗口的旋钮，就是在设计文明如何对抗热寂。**
