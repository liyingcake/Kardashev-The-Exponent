## ① 总纲

### 1.1 一句话

**把"文明"抽象成一张有向节点图：节点是设施，连线是资源流，功率是图上的血，EROI 是每条边的税，K 指数是整张图的净输出取对数。**

### 1.2 为什么是节点图

用户反馈的核心痛点是"玩法有限：没有多资源互动、没有规划、没有劳动力、没有供需"。节点图把四个痛点一次性变成**同一套可操作语法**：

| 痛点 | 节点图解答 |
|---|---|
| 多资源互动 | 每个节点有输入/输出端口，资源类型必须匹配才能连线（薪柴≠煤） |
| 规划 | 拓扑即规划：玩家每次放节点/连线都是在做"先什么后什么"的决策 |
| 劳动力 | 每个生产节点占用劳动力 L；劳动力总量=人口，自动化=用功率换劳动力 |
| 供需关系 | 输入不足=短缺（红），输出溢出=浪费（蓝），存储=缓冲——全部可视 |

### 1.3 与既有模块的关系（不推翻，只换表现层）

| 既有设计 | 在本方案中的落点 |
|---|---|
| M01 八态状态机（S1开采→S2提炼→S3发电→S4维持→S5盈余→S6科研→S7解锁→S8自动化） | 直接映射为 9 类节点（见②）。M01 的结算公式就是引擎的核心 |
| M01 五层资源链（L0生物质→L1矿物→L2金属→L3能源载体→L4高级材料） | 资源源→加工节点的层级即资源流的分层 |
| M02 科技树（5 分支 44 层） | 科技=图的"可达域扩张"：解锁新节点/新连线/升级属性（见④） |
| M04 事件与危机 | 事件=对节点的打击（枯竭/停机/减效），重连=应对危机（见⑥重连玩法） |
| M05 增量挂机 | 自动化节点=图的"脚本化"，挂机深度=自动化完成度（见⑨） |
| M03 手感层 | 轨道/殖民地作为"第二张图"或"图外图"（超长节点：跨区物流边），MVP 不做 |
| demo 主画面 Canvas | 从"玩法载体"降级为"氛围背景"，与节点图分区分职（见⑦） |

### 1.4 科学教育核心时刻

在节点图上，玩家能**看见**"这条链净赚多少功率"：链的输入能量、输出能量、净功率、EROI 全部以仪表盘+边宽+节点数字呈现。EROI<3 标黄（不可持续）、<1.5 标红（崩溃）——物理定律第一次以"图"而非"数字"的形式成为硬约束。

## ② 节点模型

### 2.1 节点类型（9 类）

| # | 类型 | ID | 图标 | 对应 M01 | 职能 | 例 |
|---|---|---|---|---|---|---|
| 1 | 资源源 | source | ⛰️🌲 | S1 上游 | 无限或有限产出原生资源流 | 森林、铁矿、河流、油田、日照 |
| 2 | 采集 | extract | ⛏️ | S1 | 把资源源转化为"已开采资源"，占劳动力 | 伐木场、矿坑、渔场 |
| 3 | 加工 | process | ⚗️🏭 | S2 | 资源升层（损耗+能耗） | 炭窑、冶炼炉、炼油厂、高炉 |
| 4 | 物流 | transport | 🐫🚂🚀 | — | 边的升级载体：降损耗、扩距离、串两地 | 道路、帆船、铁路、轨道 |
| 5 | 存储 | storage | 🏺🔋🏛️ | — | 缓冲库存，抗短缺/间歇；储能节点 | 粮仓、炭仓、电池、水库 |
| 6 | 能源转换 | convert | 🔥⚙️🔌☢️ | S3 | 能源载体→功率（热/机/电/核），带效率与废热 | 篝火、水车、蒸汽机、发电机、聚变堆 |
| 7 | 科研 | research | 🧪📚🏫 | S6 | 消耗盈余功率→产出科研点 | 观星台、书院、大学 |
| 8 | 消费 | consume | 🍲🏠🌆 | S4 | 人口维持、设施运维——负载节点 | 部落、城市、电网负载 |
| 9 | 防御 | defense | 🛡️ | — | 灾备节点，吸收事件打击 | 粮仓、防洪堤、避难所、冗余电网 |

> 映射原则：M01 的 S1 拆成 source+extract（一个管"有没有"，一个管"采不采得动"），是为了让"劳动力占用"与"资源枯竭"都有独立的可视载体。S7 解锁、S8 自动化不是节点，而是图的元操作（见④③）。

### 2.2 节点属性 Schema

每个节点统一字段：

```json
{
  "id": "firewood_source",
  "type": "source",
  "name": "薪柴森林",
  "icon": "🌲",
  "era": 0,                    // 解锁纪元
  "inputs": [],                // 端口定义：[{type:"wood", maxRate:10, required:false}]
  "outputs": [{ "type": "wood", "rate": 5 }],   // 产出端口
  "consumption": 0,            // 运转能耗(W)
  "labor": 4,                  // 占用劳动力
  "capacity": 0,               // 存储型节点才有
  "storage": { "wood": 100 },  // 当前库存
  "level": 1,                  // 科技升级等级
  "automated": false,          // 自动化状态
  "status": "running",         // running/waiting/idle/depleted/overheat/shortage/struck
  "scienceCard": "ENC-ENE-00"  // 科学卡入口
}
```

关键属性定义：
- **端口**：每个节点有固定数量的输入/输出口（见 2.4 端口数），每个口声明资源类型 + 速率上限。
- **速率 rate**：基础处理速率（资源单位/tick）。
- **能耗 consumption**：运转消耗的功率（W），从上游功率边取，不足则该节点待机。
- **劳动力 labor**：占用劳动力 L。人口=劳动力（M01 公式 6），`L_available = N×参与率 − Σ占用`。劳动力不足→节点降效（90%→50%→停机）。
- **EROI 折算**（每个节点实时可看）：
  ```
  EROI_node = 产出能量 / (输入能量 + 自身运转能耗)
  ```
  节点面板常驻显示"本节点 EROI"。
- **升级等级 level**：科技/能量投资可升级（rate×1.5、labor−20%、consumption−15% 每级，上不封顶但边际成本上升）。

### 2.3 连线（边）模型

连线是**资源管道**，不是装饰：

```json
{
  "from": "charcoal_kiln.out0",
  "to": "campfire.in0",
  "type": "charcoal",
  "maxRate": 8,           // 管道吞吐上限
  "loss": 0.05,           // 传输损耗（物流科技可降）
  "targetShare": 1.0      // 多路分岔时的分配比例
}
```

属性：
- **资源类型**：edge 只能携带一种资源。
- **maxRate**：上限流量（`F = min(上游可用, maxRate) × (1−loss)`）。
- **loss**：运输损耗。基础 10%，道路科技−20%绝对值，铁路/电网再降。
- **targetShare**：一个输出口可分多根边，按比例分配（60/40）。

### 2.4 连线规则（什么能连什么）

**硬规则四条**：

1. **端口类型匹配**：目标端口的资源类型必须等于连线携带类型。篝火（convert）输入口只收 `wood`/`charcoal`；蒸汽机只收 `coal`；消费节点只收 `food`/`power`。
2. **有向单向**：边从源端口→汇端口，禁止反向。
3. **无环保证**：节点图必须是 DAG。任何会形成有向环的连线被阻止；事件造成的"环"标记为故障环，强制拆边（见⑤3.3）。
4. **端口数量限制**：默认 convert=1入1出、process=2入1出、storage=2入2出、research=1入1出。升级节点或电网科技可加口。

**兼容表（核心，锁死组合空间以控平衡）**：

| 资源类型 | 来源 | 可连入 |
|---|---|---|
| wood 薪柴 | 森林→伐木场 | 篝火、炭窑、人口(取暖) |
| food 食物 | 农田/渔场 | 人口消费、畜力 |
| feed 饲料 | 农田/草原 | 畜力 |
| stone/wood 建材 | 采石场/林场 | 基建节点（防御/物流） |
| ore 矿石 | 矿山 | 冶炼炉 |
| metal 金属 | 冶炼炉 | 加工、物流、机械类加工 |
| charcoal 木炭 | 炭窑 | 篝火、冶炼炉 |
| coal 煤 | 煤矿 | 蒸汽机、高炉、火电 |
| oil 油 / gas 气 / uranium 铀 | 油田/气田/铀矿 | 精炼/发电 |
| **power 功率** | 能源转换 | 消费、科研、加工(驱动)、自动化 |

> 教学示例：`薪柴源→采集→篝火→热量(功率)` 合法；`薪柴源→蒸汽机` 非法——蒸汽机输入口只收 `coal`，画线时立即红色抖动并提示"蒸汽机需要煤"。

## ③ 玩法循环与玩家动线

### 3.1 核心循环：从"点一下"到"搭一条链"

```
预设模板 → 自由搭建 → 自动化 → 优化（瓶颈→分支→回投）→ 解锁更大图 → 循环
```

玩家能力随纪元线性释放（见⑥新手锁定），但**同一套图语言贯穿全程**——只是能碰的积木越来越多。

### 3.2 循环的五个动作

1. **放**：从节点库拖出新节点（受纪元/科技/能量投资限制）。
2. **连**：拖线建立资源流（受兼容表限制）。
3. **升**：能量投资升级节点（rate/labor/consumption）。
4. **化**：自动化节点（消耗功率+科研，释放劳动力，不可逆——M01 规则 D）。
5. **换**：整链换代（薪柴→煤→电→聚变），对应纪元更替。

### 3.3 0–10 分钟玩家动线示例（教学关卡串）

| 现实时间 | 玩家动作 | 图的变化 | 学会的概念 |
|---|---|---|---|
| 0:00–0:30 | 开场演出（黑暗→火光），点"取火"卡 | 加载预设模板：森林→伐木场→篝火→部落(消费) | "最小链"长什么样 |
| 0:30–2:00 | 引导点"🤖建议连线"确认唯一连线 | 链通，功率 1MW→1.5MW，K 从 0.000 微升 | 连线=资源流；功率从图上流出来 |
| 2:00–3:30 | 提示"加第二个伐木场"（复制节点，一拖即成） | 功率再涨；顶部劳动力显示"占用 8/10" | 劳动力是硬约束 |
| 3:30–4:30 | 引导在篝火前加"炭仓"存储节点 | 输出波动被缓冲，短缺高亮消失 | 存储抗波动 |
| 4:30–6:00 | 第一次自由搭建：试着把薪柴分一叉接"炭窑"，炭窑再接篝火 | 链 EROI 从 6 升到 9（木炭密度高） | 加工=EROI 杠杆（科学教育时刻①） |
| 6:00–7:30 | 炭窑输出不足，篝火输入溢出 | 瓶颈节点红色脉冲，面板提示"瓶颈：炭窑" | 找瓶颈 |
| 7:30–9:00 | 用盈余投资"自动化伐木场" | 劳动力释放，人口不再是瓶颈 | 自动化=用功率换劳动力（挂机起点） |
| 9:00–10:00 | 科研点攒够，解锁"灌溉工程" | 获得新节点"灌溉渠"，水源→灌溉渠→农田 | 科技=新积木 |

> 节奏目标：前 10 分钟完成"搭链、存储、加工、瓶颈、自动化、科技解锁"六课，玩家对图语言有完整第一印象，且全部由引导代做关键动作，无空画布恐惧。

### 3.4 优化语言（中后期核心玩法）

- **找瓶颈**：结算引擎实时给出"最紧约束"排行（输入占用率 100% 且需求仍在涨的节点），玩家一次点一个。
- **加分叉**：一条资源流分成多路（output 分岔 60/40），"既要又要"的取舍。
- **循环回投（飞轮）**：盈余功率连回科研节点→科研点→解锁新节点→更多功率。全图从"线性链"变成"飞轮"，这是中期最爽的一刻。
- **换代**：同一位置换节点（篝火→蒸汽机），旧链退役；纪元更替=换图高潮。

### 4.4 设计原则

**科技 = 图的"可达域扩张"**。科技树在节点图旁以"图膨胀树"形态展示：玩家能看到研究某科技后，图会多出哪块（预览高亮）。这使科技购买从"点数值按钮"变成"看未来的图"——每张科技卡都值得想象。

> 校验：M02 的机制解锁器清单（文字/印刷/道路/铁路/电网/卫星/互联网/聚变/超导/电梯/望远镜/疫苗/戴森云）全部能在本方案找到节点图落点，无冲突。

## ⑤ 结算引擎

### 5.1 模型：每 tick 脉冲 + 拓扑排序

- **数据结构**：有向无环图 G(V,E)。V=节点（含状态与库存），E=带资源类型/速率上限/损耗的边。
- **每 tick（100ms）**：
  1. 拓扑排序（Kahn 算法，O(V+E)）。
  2. 沿拓扑序传播资源流：每个节点读入→校验输入→按 rate 转化→写库存→推送下游。
  3. 短缺级联：下游节点输入不足→降效/待机→短缺信号沿上游传播。
  4. 汇总整图净功率→K 指数→驱动 M05 仪表盘。
- **实时重排**：连线变更即重算拓扑；发现环→拒绝该次编辑（见 3.3）。

### 5.2 核心结算量（沿用 M01 公式改写为图形式）

```
边流量:  F_edge = min(上游可用, maxRate) × (1 − loss)
节点出:  out = transform_rate(input满足?, rate × level) ；输入不满足 → out×0.5 或 0
节点耗:  power_cost = consumption × status_modifier
节点净:  P_node = out能量 − 输入能量成本 − power_cost
链净功率: P_chain = Σ P_node (全图)          → K = (log10(P_chain) − 6)/10
整链EROI: EROI_chain = Σ 链产出总能量 / Σ 链投入总能量(含维持)
盈余:     S = P_chain − P_maintain(N×100W + 运维)
科研:     dR/dt = α × S_r × (1+素养) × 范式乘数   (S≤0 → 停摆)
劳动力:   L_used = Σ labor×(1−automated) ；L_used > L_avail → 按优先级降效
```

### 5.3 库存 / 短缺 / 环路 / 失衡高亮

| 现象 | 判定 | 表现 |
|---|---|---|
| 库存 | 存储节点 `storage[type]` 每 tick 进出相抵，有容量上限 | 罐体填充动画，数字显示 |
| 短缺 | 消费/转换节点输入速率 < 需求 | 节点红色脉冲 + 面板列出"短缺清单"；短缺沿上游传播标红 |
| 溢出 | 存储满且下游取不走 | 蓝色闪光（浪费提示），建议加消费/分叉 |
| 失衡（长期） | 输出>需求持续 30s | 蓝色高亮（浪费）；输入<需求持续 30s 红色高亮（短缺） |
| 环路 | 编辑后图含环 | 阻止操作；若事件导致成环→"故障环"标记，强制拆一边（保 DAG） |

### 5.4 可视化：链的净功率与 EROI（科学教育核心时刻）

- **边**：宽度∝流量，颜色∝资源类型。
- **节点**：角标数字=该节点净输出（绿正/红负）。
- **链仪表盘（右面板常驻）**：
  ```
  这条链：
  投入  X W  ──▶  产出  Y W  ──▶  净赚  Z W（EROI Y/X = 6.4）
  废热  W W（卡诺效率提示）
  EROI<3 标黄"不可持续" / <1.5 标红"即将崩溃"
  ```
- **整图汇总**：文明总功率 → 顶栏 K 刻度尺联动。
- **教育设计**：玩家改一条线，仪表盘立刻变——"把 EROI 从 6 拉到 9"就是一次物理课。

### 5.5 复杂度与防死锁

- 规模：教学段 20–50 节点；全游戏峰值 100–200 节点。拓扑排序每 tick 开销微秒级，100ms tick 毫无压力。
- 防死锁：DAG 保证无循环等待；短缺只降效不冻结；无"僵尸节点"。
- 性能保险：节点>200 时降频结算（500ms/tick）或区域分区结算（轨道图独立）。

## ⑥ 上手门槛控制（防蓝图劝退）

UE Blueprint 劝退的根因：**空画布 + 全自由连线 + 海量节点**。对策是一整套"引导下的受限自由"：

### 6.1 预设模板优先

- 前 4 纪元全部**以模板开局**：森林→伐木场→篝火→部落 已连好。玩家只做"调图"（加节点/换线/升级），不做"搭图"。
- 模板库：每纪元 2–3 套（薪柴部落、农耕城邦、商路帝国…），一键切换，旧节点自动退役。

### 6.2 新手锁定（三阶段渐进解锁）

| 阶段 | 纪元 | 可用节点类 | 连线方式 |
|---|---|---|---|
| 1 学徒 | 火种–农耕 | source / extract / convert / consume | 只能点"建议连线"确认，不能自由拖线 |
| 2 工匠 | 青铜–前工业 | + process / storage | 可拖"同类端口"（自动吸附，吸附成功才允许） |
| 3 工程师 | 工业及以后 | + transport / research / defense | 全自由连线 + 分岔 + 加端口 |

- 全阶段禁止"空放节点"：节点必须至少连上一条输入或输出才激活，否则显示为灰色占位。

### 6.3 自动连线建议 + 错误红线

- 🤖 建议按钮：高亮推荐下一条边（按"当前最短缺"计算），一键铺设。
- 非法连线：红色抖动 + tooltip 原因（"蒸汽机需要煤，不是薪柴"）。
- 节点面板所有端口 hover 显示可连列表，避免猜。

### 6.4 教学关卡

8 关脚本（对应 3.3 动线）：点火→连采→加存→加工→找瓶颈→自动化→科研回投→换代。每关 1–2 分钟，完成即解锁对应连线自由。

### 6.5 术语翻译

界面禁用"拓扑排序/EROI/吞吐"等词，统一翻译：
- EROI → "这条链赚不赚"
- 拓扑/环路 → "线不能绕回自己"
- 短缺 → "缺原料"
- 瓶颈 → "卡住的地方"

## ⑧ 实现可行性

### 8.1 规模评估

| 部分 | 预估代码量 | 复杂度 |
|---|---|---|
| 数据层（节点/边/兼容表/模板） | ~400 行 | 低（JSON 配置） |
| 结算引擎 engine.js（拓扑+脉冲+短缺级联） | ~600 行 | 中（教科书算法） |

| 教学引导 tutorial.js | ~400 行 | 低（脚本） |

| 合计 | **新增 ~2,200 行 + 改造 ~700 行** | — |

**人力估计**：1 名熟练前端 2–3 周做出可玩垂直切片（含 8 教学关）；4–6 周含节点库扩充与平衡。

### 8.2 从现有 demo 演进路线（改动量）

现状：game.js 475 + data.js 111 + scene.js 287 + index.html 146 ≈ **1,019 行**。

| 改动项 | 量级 | 说明 |
|---|---|---|
| data.js | 重写 | 新 Node/Link/兼容表/模板结构（保留科学卡与纪元数据） |
| 新增 engine.js | 全新 | 替换现有 `growthRate()` 指数增长公式 |
| 新增 graph.js | 全新 | Canvas 节点图（不复用现有 HTML 列表 UI） |
| game.js | 重构 ~60% 保留 | 存档/事件/纪元/特质逻辑保留；增长率与设施购买逻辑替换为图结算 |
| scene.js | 保留 + ~200 行联动 | 从玩法驱动改为读图状态驱动氛围 |
| index.html/style.css | 布局重构 | 左/中列合并进图面板，新增信息面板 |

**一句话**：一次"换引擎不换壳"的中等重构，**不是推倒重来**——K 指数、科学卡、事件、纪元、特质、存档全部原样保留。

### 8.3 关键技术取舍

- 节点图绘制用**原生 Canvas2D**（无需引入图形库，节点形状只有方框/圆角框/端口小圆）。
- 连线交互第一版只做"端口到端口拖拽 + 自动吸附"，不做任意贝塞尔自由画——复杂度砍半。
- 布局第一版用**网格自动布局**（按拓扑序左右排列），不追求"自由拖放美观"，后期再加手拖。

## ⑨ 风险与对策

| 风险 | 描述 | 对策 |
|---|---|---|
| 蓝图劝退 | 节点编辑器复杂度吓跑休闲挂机玩家 | ⑥全章：模板优先+三阶段锁定+建议连线+错误提示+术语翻译 |
| 与"挂机"矛盾 | 节点图需要高频手动操作，破坏增量挂机本质 | 自动化节点=图脚本化：自动化后该节点持续运转、面板只读仪表盘；挂机深度=自动化完成度；离线收益按"已自动化比例"结算（衔接 M05 Q5） |
| 图爆炸 | 自由搭建导致玩家迷失/性能问题 | 端口数限制+兼容表锁死组合空间；网格自动布局；O(V+E) 结算撑 200 节点 |
| 平衡失控 | 自由连线让数值不可预测 | 资源类型兼容表 = 有限的组合空间（可枚举验证）；边 maxRate 上限；节点升级边际成本上升防单点爆炸（沿用 M01 公式 7） |
| 科学教育稀释 | 玩家只摆图不学科学 | 每个节点/边挂科学卡；链 EROI 仪表盘常驻；"改造线→仪表盘立刻变"即教育时刻；科学顾问彩蛋（卡诺等）挂在 convert 节点 |
| 与 K 指数脱节 | 玩图玩嗨了忘掉灵魂指标 | K 刻度尺顶栏常驻；链净功率实时映射 K；纪元更替=换图高潮演出（衔接 M02 里程碑协议） |
| 事件打断挫败感 | 节点被枯竭/停机玩家觉得"白搭了" | 事件打击=**重连机会**（见下）；被打击节点可修复/重建，保留玩家布局不删除 |
| 环路/死锁实现坑 | DAG 校验与事件注入冲突 | 引擎层强制无环；事件注入"枯竭"只改节点状态不破坏拓扑；故障环显式标记并强制拆边 |

### 9.1 事件→重连的玩法化（M04 衔接）

事件=对节点的打击，玩家反应=改图，危机成为内容：

| 事件 | 节点表现 | 玩家重连动作 |
|---|---|---|
| 森林枯竭 | 薪柴 source 流速衰减→归零 | 拆薪柴线，接水车/畜力链（换代） |
| 小冰期 | 农田 source 减产 40% | 加粮仓（defense 节点）+ 加煤炭分支 |
| 洪水毁坝 | 水车 convert 停机 | 修复或改道蒸汽链 |
| 石油峰值 | 油田 source 产量先升后降 | 天然气/裂变/聚变分支接续 |

设计红线：事件**永远不删除玩家布局**，只改变节点状态（枯竭/减效/停机）——玩家在旧图上"做手术"而非"重拼"，保住沉没成本与代入感。
