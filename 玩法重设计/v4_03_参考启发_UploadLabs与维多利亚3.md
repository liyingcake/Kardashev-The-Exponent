## 1. 从《Upload Labs》（节点·供需·联系）得到的启发

> 核心母题：**游戏玩的是"结构"，不是"数量"。**

| 启发 | 一句话 | 落地到 v4 |
|---|---|---|
| **H1 节点是"功能单元"不是"数值单元"** | 每个节点有明确的输入端口/输出端口/功能，价值来自它"做了什么" | v4 节点分采集/加工/分配/消费/收集五功能类，每类只做一件事 |
| **H2 连线即玩法** | 供需关系通过连线显式表达，连错/断链 = 玩法事件 | v4 的分配节点带吞吐容量，连线是"物流"，断链=危机 |
| **H3 结构即结果** | 玩家搭出的"图的结构"决定产出，而非"放了几个" | v4 的整合系数按"链完整度"给乘数，摊大饼无加成 |
| **H4 瓶颈可视化** | 最窄一环被高亮，玩家的规划 = 找瓶颈 | v4 供需缺口 + 吞吐瓶颈实时显示在窗口 |

**一句话转化**：Upload Labs 教我"节点要串联成有意义的图"——这正是病灶 A（并列堆量）的解药。

## 2. 从《维多利亚3》（经济体量·运营·规模效应）得到的启发

> 核心母题：**经济体是一个"供需 + 乘数"的系统，不是一堆仓库。**

| 启发 | 维3 原机制 | 落地到 v4 |
|---|---|---|
| **H5 供需→信号** | 市场供需决定价格/利润，玩家靠"信号"运营 | v4 定居点消费=需求；供<需→劳动力/科技下降，供>需→盈余可投资 |
| **H6 生产方式（Production Methods）** | 建筑可切换配方，科技解锁的是"更优配方"而非纯 +buff | v4 科技解锁"加工配方"（如 灶火→烤炉，同投入更多熟食） |
| **H7 规模经济（Economy of Scale）** | 更大建筑（更多等级）→ 单位投入产出更高（吞吐加成） | v4 规模系数：链吞吐过阈值→效率递增；**集中 > 分散** |
| **H8 POP 双重身份** | 人口既消费商品，又提供劳动力 | v4 定居点既是"消费端"又是"劳动力源"，闭环自洽 |
| **H9 经济体量可运营** | 盈余可再投资（建厂/扩产/研究） | v4 盈余 = 投资乘数/科技/扩张链，运营是玩家的决策空间 |

**一句话转化**：维多利亚3 教我"经济体靠乘数与规模成长"——这正是病灶 C/F（乘数散落、无规模效应）的解药。

## 3. 两条参考的合流：v4 的"双引擎"

```
《Upload Labs》  ── 结构/连线/供需 ──→  节点管线层（怎么连、瓶颈在哪）
《维多利亚3》    ── 经济/规模/乘数 ──→  窗口乘数层（多高效、多大规模）

                     ↓ 合流 ↓
         v4 = 一条有目的的产业链 × 一个可分解的效率乘数
```

- **结构层**（Upload Labs）回答："我的文明是怎么运转的？"——靠一张功能管线图。
- **经济层**（维多利亚3）回答："我的文明运转得多好？"——靠一个窗口里的总乘数。

两者不是二选一，而是**同一件事的两个视角**：节点是工序，乘数是效率。这正好对应你说的"一个窗口 + 一个表达乘数的小乘数"。

## 4. 一句话总结

> 《Upload Labs》给骨架（串联、连线、供需、找瓶颈），《维多利亚3》给血肉（经济体量、规模经济、可运营的乘数）。合起来 = **"经营一条会呼吸的产业链，用一个小乘数衡量文明的效率"**——这就是 v4。
